# item-bank-php 비즈니스 규칙 후보

> 대상: `legacy/item-bank-php/` (읽기 전용 분석). 선행 문서: [ARCHITECTURE.md](ARCHITECTURE.md), [ERD.md](ERD.md)
> 근거는 저장소 파일의 `파일:줄번호` 다. 코드 · SQL 을 읽어서만 뽑았고, 화면을 띄우거나 DB 에 쿼리를 실행해 확인하지 않았다.
> 경로는 `legacy/item-bank-php/` 를 생략해 적는다. 스키마는 `db/mariadb/init/01-schema.sql` 이다.

## 0. 요약

- 규칙 후보 30개: 문항 검색 조건 14개(BR-01 ~ BR-14), 정렬 · 페이지 7개(BR-15 ~ BR-21), 등록 · 검증 7개(BR-22 ~ BR-28), 단원 목록 · 선택 목록 2개(BR-29 ~ BR-30).
- 확신도: 확실 30개 / 추정 0개. 추정으로만 올릴 규칙은 따로 두지 않고, 추정되는 동작은 해당 규칙의 비고에 "추정"으로 적었다.
- 이관 때 특히 확인이 필요한 것
  1. **난이도를 비우면 난이도 5 가 빠진다**(BR-07). 주석은 "1~5 모두 포함"이라 주석과 코드가 다르다.
  2. **기본 정렬은 `level DESC, id ASC`**(BR-15). 단원 정렬도 2차 키가 항상 `level DESC` 다(BR-17).
  3. **잘못된 검색 입력은 오류가 아니라 경고 + 그대로 조회**다(BR-05 · BR-06 · BR-09 · BR-12). 난이도 `3abc` 는 PHP 정수 변환으로 난이도 3 검색이 된다(BR-09 비고).
  4. **수정 · 삭제 화면은 이 모듈에 없다.** 요청 범위의 "수정 시의 검증"에 해당하는 코드는 찾지 못했다(`item` 에 UPDATE · DELETE 가 없음, ERD.md 3.1).

## 1. 문항 검색 — 대상과 조건 조합 (`search.php`)

### BR-01 검색 대상은 공개 문항뿐이다
- 규칙: 문항 검색은 `status = 'A'` 인 문항이면 결과에 넣고, 그 밖의 상태(`R` · `D` 등)이면 넣지 않는다.
- 근거: `search.php:522`, `db/mariadb/init/01-schema.sql:52,68-70`
- 근거 코드:
  ```php
  $from   = " FROM v_item_public";
  ```
  ```sql
  FROM item i
  JOIN unit u ON u.id = i.unit_id
  WHERE i.status = 'A';
  ```
- 확신도: 확실
- 비고: 상태 값의 의미(A=공개 D=삭제 R=검수중)는 스키마 주석만 있다(`01-schema.sql:26`). 같은 "공개 = `status='A'`" 규칙이 단원 목록에는 뷰가 아니라 SQL 리터럴로 따로 구현돼 있다(BR-29). 스키마 주석 `01-schema.sql:51` 은 "등록 화면도 이 뷰를 기준으로 삼는다"고 하지만 `register.php` 는 이 뷰를 쓰지 않는다(주석과 코드 불일치).

### BR-02 검색 조건은 모두 AND 로 결합한다
- 규칙: 키워드 · 단원 · 난이도 · 태그가 여러 개 주어지면 모든 조건을 만족하는 문항만 찾는다.
- 근거: `search.php:44,98,118,215,218,244-245,525-526`
- 근거 코드:
  ```php
  $where    = " WHERE 1=1";
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  $where .= " AND unit_code = ?";
  ```
- 확신도: 확실
- 비고: OR 결합 옵션은 없다. 건수 SQL 과 목록 SQL 이 같은 `$where` 를 쓴다(`:525-526`).

### BR-03 조건 파라미터가 배열로 오면 첫 값만 쓴다
- 규칙: `q` · `unit` · `level` · `tag` · `sort` · `dir` · `page` 가 배열(`?tag[]=a&tag[]=b`)이면 첫 번째 값 하나만 조건으로 쓴다.
- 근거: `search.php:55,59,63,67,71,75,79`
- 근거 코드:
  ```php
  $tag = is_array($params['tag']) ? (string)reset($params['tag']) : (string)$params['tag'];
  ```
- 확신도: 확실
- 비고: 태그 · 단원 · 난이도 다중 선택은 지원하지 않는다는 뜻이다. 모든 조건값은 앞뒤 공백을 지운 뒤 쓴다(`:85,109,211,235,266-267`).

### BR-04 키워드는 제목 또는 지문의 부분 일치로 찾는다
- 규칙: 키워드가 비어 있지 않으면 제목이나 지문 중 하나라도 키워드를 포함하는 문항을 찾는다.
- 근거: `search.php:90,97-98`
- 근거 코드:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- 확신도: 확실
- 비고: 키워드 안의 `%` · `_` 는 이스케이프하지 않아 와일드카드로 동작한다. 막지 않고 경고만 낸다(`:94-95`). 컬럼 콜레이션이 `utf8mb4_unicode_ci`(`01-schema.sql:33`)라 대소문자를 가리지 않고 일치할 것으로 추정한다(실행 확인 안 함). 한 글자 키워드는 경고만 내고 그대로 검색한다(`:91-92`).

### BR-05 키워드는 100자까지만 쓴다
- 규칙: 키워드가 100자를 넘으면 앞 100자로 자르고 경고를 낸 뒤 검색한다.
- 근거: `search.php:86-88`, `search.php:494`
- 근거 코드:
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 같은 100 이 입력 폼 `maxlength="100"`(`:494`)에도 따로 들어가 있다. 매직 넘버(3장).

### BR-06 단원은 단원 코드 완전 일치로 찾고, 형식이 틀려도 조회한다
- 규칙: 단원 코드가 비어 있지 않으면 `unit_code = 입력값` 으로 찾고, 형식이 틀리거나 소문자가 섞였거나 없는 코드여도 경고만 내고 그대로 조회한다.
- 근거: `search.php:110-120`, `search.php:141-142`
- 근거 코드:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
      // 형식이 달라도 그대로 조회한다 (결과는 대개 0건)
  $where .= " AND unit_code = ?";
  ```
- 확신도: 확실
- 비고: 형식 정규식은 영문 1자 + 숫자 1~2자 + `-` + 숫자 1~2자. 소문자 경고 문구는 "입력값 그대로 조회합니다"(`:116`)이지만, `unit` 콜레이션이 `utf8mb4_unicode_ci`(`01-schema.sql:18`)라 `m5-1` 도 `M5-1` 과 일치할 것으로 추정한다(실행 확인 안 함). 없는 코드 경고(`:142`)는 `unit` 테이블 조회로 판단한다(`:125`).

### BR-07 난이도를 비우면 난이도 5 를 뺀다
- 규칙: 난이도 값이 비어 있으면 `level < 5` 조건을 붙여 난이도 1~4 문항만 찾는다.
- 근거: `search.php:213-216`
- 근거 코드:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- 확신도: 확실
- 비고: **주석과 코드 불일치.** 주석은 "1~5 모두 포함", 코드는 난이도 5 제외. 폼의 빈 값 라벨도 "전체"(`:192`)라 화면 문구와도 어긋난다. 조건 요약(`$summary`)에 아무것도 추가하지 않아 조건이 없으면 "조건 없이 검색했습니다"로 표시된다(`:355-356`) — 사용자에게 제외 사실이 드러나지 않는다. 의도 여부는 ARCHITECTURE.md 6장에서도 미확인으로 남아 있다. 이관 시 characterization 스냅샷은 이 동작(5 제외)을 기준으로 찍힌다.

### BR-08 난이도가 1~5 한 자리 숫자면 그 난이도와 일치하는 문항만 찾는다
- 규칙: 난이도 값이 `1`~`5` 중 하나면 `level = 값` 으로 찾는다.
- 근거: `search.php:217-221`
- 근거 코드:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- 확신도: 확실
- 비고: 이 경우에는 난이도 5 도 조회된다(BR-07 과 대비). 같은 1~5 범위 검증이 등록(`register.php:70`)에도 같은 정규식으로 있다.

### BR-09 난이도가 1~5 밖이면 경고 후 정수 변환 값으로 찾는다
- 규칙: 난이도 값이 비어 있지 않고 `1`~`5` 한 글자가 아니면 경고를 내고 `(int)값` 과 같은 난이도를 찾는다.
- 근거: `search.php:223-229`
- 근거 코드:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- 확신도: 확실
- 비고: 주석은 "대개 0건"(`:224`)이지만, PHP 7.4 의 `(int)` 는 앞쪽 숫자를 읽으므로 `3abc` · `3.7` · `03` 은 3 으로 바뀌어 **난이도 3 문항이 조회된다**(PHP 언어 동작에서 추정, 실행 확인 안 함). `abc` 는 0 → 0건, `6` 은 6 → 0건(스키마에 CHECK 가 없어 6 이 저장돼 있으면 나온다, `01-schema.sql:25`).

### BR-10 태그는 태그 이름 완전 일치로 찾는다
- 규칙: 태그 값이 비어 있지 않으면 그 이름의 태그가 붙은 문항만 찾는다.
- 근거: `search.php:236,244-245`
- 근거 코드:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- 확신도: 확실
- 비고: `=` 비교라 `%` · `_` 는 와일드카드가 아니다. 경고 문구는 "부분 일치를 지원하지 않습니다"(`:237-238`). 태그 id 가 아니라 이름으로 찾는다. 대소문자는 콜레이션(`01-schema.sql:40`)상 가리지 않을 것으로 추정.

### BR-11 태그 이름은 50자까지만 쓴다
- 규칙: 태그 값이 50자를 넘으면 앞 50자로 자르고 경고를 낸 뒤 검색한다.
- 근거: `search.php:240-242`
- 근거 코드:
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
  ```
- 확신도: 확실
- 비고: 50 은 `tag.name VARCHAR(50)`(`01-schema.sql:37`)과 같은 값이지만 코드에 리터럴로 따로 있다.

### BR-12 등록되지 않은 태그여도 조회는 한다
- 규칙: 태그 값이 태그 목록에 없으면 "등록되지 않은 태그" 경고를 내고 조회는 그대로 한다.
- 근거: `search.php:250-260`
- 근거 코드:
  ```php
  // 등록된 태그인지 확인 (없어도 조회는 그대로 한다 → 0건)
  if (!$tagKnown) {
      $warnings[] = '등록되지 않은 태그입니다: ' . $tag;
  ```
- 확신도: 확실
- 비고: 목록 대조는 PHP `===`(대소문자 구분, `:253`), 실제 조회는 DB 콜레이션(대소문자 무시 추정)이라 대소문자만 다른 태그는 **경고가 나면서도 결과가 나올 수 있다**(추정, 실행 확인 안 함). 단원 코드(BR-06)도 같은 구조다.

### BR-13 결과가 0건이면 안내 문구를 내고 표를 그리지 않는다
- 규칙: 총 건수가 0이면 "검색 결과가 없습니다"를 출력하고 결과 표 · 페이지 링크를 출력하지 않는다.
- 근거: `search.php:657-660`
- 근거 코드:
  ```php
  if ($total === 0) {
      echo '<p id="message">검색 결과가 없습니다</p>' . "\n";
      return;
  ```
- 확신도: 확실
- 비고: 건수(`<p id="count">`)는 0건일 때도 먼저 출력된다(`:655`).

### BR-14 조건이 하나도 없으면 "조건 없이 검색했습니다"로 표시한다
- 규칙: 키워드 · 단원 · 난이도(1~5 또는 잘못된 값) · 태그 요약이 하나도 없으면 "조건 없이 검색했습니다"를 표시한다.
- 근거: `search.php:355-356`
- 근거 코드:
  ```php
  if (empty($summary)) {
      $summaryHtml = '<p class="summary">조건 없이 검색했습니다.</p>' . "\n";
  ```
- 확신도: 확실
- 비고: 이때도 `level < 5` 조건은 붙어 있다(BR-07). 화면 문구와 실제 조건이 다르다.

## 2. 문항 검색 — 정렬 · 페이지 (`search.php`)

### BR-15 정렬 기준이 없으면 난이도 내림차순, 같은 난이도면 번호 오름차순으로 정렬한다
- 규칙: `sort` 가 비어 있으면 `level DESC, id ASC` 로 정렬한다.
- 근거: `search.php:317-320`
- 근거 코드:
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: 기본 정렬에서는 `dir` 을 무시한다(`dir=asc` 여도 `level DESC`). 기본 정렬일 때 `$sort` 가 `''` 이라 `dir` 은 화면 표시용으로도 채워지지 않는다(`:328`).

### BR-16 알 수 없는 정렬 기준이면 경고 후 기본 정렬을 쓴다
- 규칙: `sort` 가 `id` · `title` · `unit` · `level` · `created` 가 아니면 경고를 내고 BR-15 기본 정렬을 쓴다.
- 근거: `search.php:266,322-326`
- 근거 코드:
  ```php
  default:
      $warnings[] = '알 수 없는 정렬 기준입니다. 기본 정렬을 사용합니다.';
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- 확신도: 확실
- 비고: `sort` 는 소문자로 바꾼 뒤 비교한다(`:266`). 기본 정렬 SQL 문자열이 `:319` 와 `:325` 두 곳에 중복돼 있다. `created` 는 정렬 파라미터로는 받지만 열 머리글 링크에는 없다(`:392-397`).

### BR-17 정렬 기준별 방향 기본값과 2차 정렬 키
- 규칙: `dir` 이 `asc` · `desc` 가 아니면(빈 값 포함) `id` · `title` · `unit` 은 오름차순, `level` · `created` 는 내림차순으로 정렬하고, 2차 키는 아래 표와 같다.
- 근거: `search.php:268-273,276-315,328-331`
- 근거 코드:
  ```php
  $orderBy = " ORDER BY unit_code ASC, level DESC, id ASC";
  $dir = ($sort === 'level' || $sort === 'created') ? 'desc' : 'asc';
  ```
- 확신도: 확실
- 비고: 잘못된 `dir`(예: `up`)은 경고를 낸다(`:269-270`). 정렬 기준별 SQL:

  | sort | dir 기본 | asc | desc | 근거 |
  |---|---|---|---|---|
  | `id` | asc | `id ASC` | `id DESC` | `:277-283` |
  | `title` | asc | `title ASC, id ASC` | `title DESC, id ASC` | `:285-291` |
  | `unit` | asc | `unit_code ASC, level DESC, id ASC` | `unit_code DESC, level DESC, id ASC` | `:293-299` |
  | `level` | desc | `level ASC, id ASC` | `level DESC, id ASC` | `:301-307` |
  | `created` | desc | `created_at ASC, id ASC` | `created_at DESC, id ASC` | `:309-315` |

  `unit` 정렬은 방향과 상관없이 2차 키가 `level DESC` 고정이다. 모든 정렬의 마지막 키가 `id ASC` 라 순서가 결정적이다(`id` desc 제외).

### BR-18 난이도 열 머리글은 첫 클릭에 내림차순이다
- 규칙: 현재 정렬이 난이도가 아니면 난이도 머리글 링크는 `dir=desc`, 나머지 머리글은 `dir=asc` 로 만든다. 현재 정렬 중인 열은 방향을 뒤집은 링크를 만든다.
- 근거: `search.php:400-413`
- 근거 코드:
  ```php
  } else if ($key === 'level') {
      // 난이도는 첫 클릭에 내림차순
      $nextDir = 'desc';
  ```
- 확신도: 확실
- 비고: 화면 동작 규칙. 정렬 링크는 현재 키워드 · 단원 · 난이도 · 태그를 유지하고 `page` 는 빼서 1페이지로 돌아간다(`:369-387,414-415`).

### BR-19 한 페이지는 20건이다
- 규칙: 검색 결과는 페이지당 20건을 `(page - 1) * 20` 부터 보여 준다.
- 근거: `search.php:349,523,553`
- 근거 코드:
  ```php
  $offset = ($page - 1) * 20;
  $limit  = " LIMIT 20 OFFSET " . (int)$offset;
  'page_size'    => 20,
  ```
- 확신도: 확실
- 비고: 20 이 세 곳에 리터럴로 중복돼 있다. 매직 넘버(3장).

### BR-20 페이지 번호는 1~999 로 보정한다
- 규칙: 페이지 값이 숫자가 아니면 1페이지(경고), 1 미만이면 1페이지(경고 없음), 999 를 넘으면 999페이지(경고)로 바꾼다.
- 근거: `search.php:336-348`
- 근거 코드:
  ```php
  if (preg_match('/^[0-9]+$/', $pageRaw)) {
  } else if ($pageRaw !== '' && $pageRaw !== '1') {
  if ($page > 999) {
  ```
- 확신도: 확실
- 비고: `page=0` 은 숫자라 경고 없이 1로, `page=-1` · `page=abc` 는 경고와 함께 1로 간다. 빈 값은 경고 없음. 999 는 매직 넘버(3장). 총 페이지를 넘는 번호(예: 결과 30건에 `page=5`)는 보정하지 않는다 — 건수는 30으로 표시되고 표는 빈 채로 나올 것으로 추정(`:657` 이 `$total` 로만 판단, 실행 확인 안 함).

### BR-21 페이지 링크는 전체 페이지가 2 이상일 때만 출력한다
- 규칙: `ceil(총 건수 / 20)` 이 1 이하면 페이지 링크를 출력하지 않고, 2 이상이면 이전 · 1..N · 다음 링크를 출력한다.
- 근거: `search.php:685-703`
- 근거 코드:
  ```php
  $pages = (int)ceil($total / $pageSize);
  if ($pages > 1) {
  ```
- 확신도: 확실
- 비고: 1..N 을 모두 출력한다(생략 없음). 페이지 링크는 현재 조건과 정렬을 유지한다(`:423-430`).

## 3. 문항 등록 · 검증 (`register.php`)

> 등록 화면만 있다. 수정 · 삭제 화면과 UPDATE · DELETE SQL 은 이 모듈에 없다.
> 검증은 모두 서버(POST 처리부)에서 하고, 하나라도 실패하면 저장하지 않고 오류 목록을 보여 준다(`register.php:83,133-139`).

### BR-22 제목은 앞뒤 공백을 지운 뒤 5자 이상 200자 이하여야 한다
- 규칙: 앞뒤 공백을 지운 제목이 5자 미만이거나 200자를 넘으면 등록하지 않고 오류를 낸다.
- 근거: `register.php:41,49-54`
- 근거 코드:
  ```php
  if (mb_strlen($title, 'UTF-8') < 5) {
  if (mb_strlen($title, 'UTF-8') > 200) {
  ```
- 확신도: 확실
- 비고: 주석 "공백 제외 아님, 앞뒤 공백만 제거"(`:48`)와 코드가 일치한다(가운데 공백은 글자 수에 포함). 200 은 `item.title VARCHAR(200)`(`01-schema.sql:23`)과 같다. 폼 라벨은 "5자 이상"만 알리고(`:143`) 입력 필드에 `maxlength` 가 없다(`:144`). 5 · 200 은 매직 넘버(3장).

### BR-23 지문은 비어 있으면 안 된다
- 규칙: 앞뒤 공백을 지운 지문이 빈 문자열이면 등록하지 않고 오류를 낸다.
- 근거: `register.php:42,56-58`
- 근거 코드:
  ```php
  if ($stem === '') {
      $errors[] = '지문을 입력해야 합니다.';
  ```
- 확신도: 확실
- 비고: 지문 길이 상한은 코드에 없다(컬럼은 `TEXT`, `01-schema.sql:24`).

### BR-24 단원은 단원 목록에 있는 id 여야 한다
- 규칙: 제출한 `unit_id` 가 `unit` 테이블의 id 중 하나와 문자열로 같지 않으면 등록하지 않고 "단원을 선택해야 합니다" 오류를 낸다.
- 근거: `register.php:27,60-68`
- 근거 코드:
  ```php
  if ((string)$u['id'] === $unitId) {
      $unitOk = true;
  ```
- 확신도: 확실
- 비고: 문자열 완전 비교라 `01` 처럼 앞에 0 이 붙은 값은 거부된다. 미선택과 없는 id 가 같은 문구로 처리된다.

### BR-25 난이도는 1~5 한 자리 숫자여야 한다
- 규칙: 난이도가 `1`~`5` 한 글자가 아니면 등록하지 않고 오류를 낸다.
- 근거: `register.php:70-72`, `register.php:163`
- 근거 코드:
  ```php
  if (!preg_match('/^[1-5]$/', $level)) {
      $errors[] = '난이도는 1~5 사이여야 합니다.';
  ```
- 확신도: 확실
- 비고: 같은 범위가 폼 선택지 루프 `for ($i = 1; $i <= 5; $i++)`(`:163`), 검색의 정규식(`search.php:217`), 검색 라벨 배열(`search.php:193-199`)에 따로 구현돼 있다. DB 에는 CHECK 제약이 없고 주석만 있다(`01-schema.sql:25`). 검색에서는 잘못된 값이 오류가 아닌 경고인 것(BR-09)과 달리 등록에서는 오류다.

### BR-26 태그 목록에 없는 태그 id 는 오류 없이 버린다
- 규칙: 제출한 태그 id 중 `tag` 테이블에 없는 것은 오류를 내지 않고 저장 대상에서 뺀다. 태그는 0개여도 된다.
- 근거: `register.php:45,74-81,104`
- 근거 코드:
  ```php
  if ((string)$t['id'] === (string)$tid) {
      $validTagIds[] = (int)$tid;
  ```
- 확신도: 확실
- 비고: 같은 태그 id 를 두 번 보내면 `$validTagIds` 에 중복이 남고(중복 제거 없음), `item_tag` PK(`01-schema.sql:45`) 위반으로 `execute` 가 실패해 전체 등록이 롤백되고 "저장 중 오류가 발생했습니다"가 날 것으로 추정한다(`register.php:108-109,119-122`, 실행 확인 안 함). 태그 개수 상한은 코드에 없다.

### BR-27 등록한 문항은 검수중(`R`) 상태로 저장한다
- 규칙: 검증을 통과한 문항은 `status = 'R'`, `created_at` · `updated_at` = DB `NOW()` 로 저장한다.
- 근거: `register.php:84,93-94,116`
- 근거 코드:
  ```php
  "INSERT INTO item (id, unit_id, title, stem, level, status, created_at, updated_at)
   VALUES (?, ?, ?, ?, ?, 'R', NOW(), NOW())"
  ```
- 확신도: 확실
- 비고: BR-01 · BR-29 와 합쳐, 등록 직후 문항은 검색과 단원별 공개 문항 수에 나오지 않는다. 주석(`:84`)과 완료 문구 "검수 완료 후 검색에 노출됩니다"(`:116`)가 코드와 일치한다. `R` → `A` 전환 경로는 이 모듈에 없다(ERD.md 4장). 스키마 기본값은 `'A'`(`01-schema.sql:26`)라, 이 INSERT 를 거치지 않고 status 를 생략하면 공개로 들어간다.

### BR-28 문항 번호는 현재 최대 번호 + 1 이고, 문항과 태그는 한 트랜잭션으로 저장한다
- 규칙: 새 문항 id 는 `COALESCE(MAX(id), 0) + 1` 이고, 문항 INSERT 와 태그 INSERT 중 하나라도 실패하면 모두 롤백한다.
- 근거: `register.php:85,87,99-101,108-110,114,119-120`
- 근거 코드:
  ```php
  $res = $conn->query("SELECT COALESCE(MAX(id), 0) + 1 AS next_id FROM item FOR UPDATE");
  $conn->rollback();
  ```
- 확신도: 확실
- 비고: 문항이 하나도 없으면 1번부터. `item.id` 는 AUTO_INCREMENT 가 아니다(`01-schema.sql:21`). 동시 등록 안전성은 미확인(ERD.md 4장). `mysqli_report(MYSQLI_REPORT_OFF)`(`inc/db.php:20`)라 SQL 실패는 예외가 아니라 `execute()` 의 `false` 로 감지하고 `RuntimeException` 을 직접 던진다. 성공하면 입력값을 비운다(`:117-118`).

## 4. 단원 목록 · 선택 목록

### BR-29 단원별 문항 수는 공개 문항만 센다
- 규칙: 단원 목록의 문항 수는 그 단원의 `status = 'A'` 문항만 세고, 문항이 없는 단원도 0 으로 표시한다.
- 근거: `units.php:15-19`
- 근거 코드:
  ```php
  // 단원별 공개(status='A') 문항 수. 삭제 · 검수중 문항은 세지 않는다.
  (SELECT COUNT(*) FROM item i WHERE i.unit_id = u.id AND i.status = 'A') AS item_count
  ```
- 확신도: 확실
- 비고: 같은 "공개 = A" 규칙이 검색에서는 뷰(`01-schema.sql:70`)로, 여기서는 SQL 리터럴로 **두 곳에 따로 구현**돼 있다. 뷰와 달리 여기는 난이도 5 를 빼지 않는다 — 단원 목록의 개수와 조건 없는 검색 건수는 난이도 5 공개 문항 수만큼 다를 수 있다(BR-07).

### BR-30 단원은 학년 → 코드 순, 태그는 id 순으로 나열한다
- 규칙: 단원 목록 · 단원 선택지는 `grade ASC, code ASC`, 태그 선택지는 `id ASC` 로 정렬하고, 검색 폼의 단원 선택지는 학년별로 묶는다.
- 근거: `units.php:19`, `register.php:27,34`, `search.php:156,178,165-169,452-462`
- 근거 코드:
  ```php
  $res = $conn->query("SELECT code, name, grade FROM unit ORDER BY grade ASC, code ASC");
  $res = $conn->query("SELECT name FROM tag ORDER BY id ASC");
  ```
- 확신도: 확실
- 비고: 같은 정렬 SQL 이 세 파일에 따로 있다. 검색 결과의 태그 문자열(`tag_names`)도 태그 id 순으로 쉼표로 잇는다(`01-schema.sql:64`). 단원 코드 정렬은 문자열 정렬이라 `M10-1` 이 `M5-1` 보다 앞에 올 수 있다(추정, 시드 데이터로 확인 안 함).
