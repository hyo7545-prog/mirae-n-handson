# 레거시 모듈 문서화

- 분석 대상 폴더(`$ARGUMENTS` 의 모듈 경로)의 파일은 읽기만 한다. 수정 · 이동 · 삭제하지 않는다.
- 쓰는 파일은 `docs/<모듈명>/` 아래 네 개뿐이다: `ARCHITECTURE.md` · `ERD.md` · `BUSINESS-RULES.md` · `CROSS-CHECK.md`.
- `<모듈명>` 은 폴더 이름이 아니라 `item-bank` | `assignment` | `grade` 중 하나다.
  - `legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`
  - 셋 중 어디에도 맞지 않으면 멈추고 사람에게 묻는다.
- 범위 제한 인자가 있으면 그 범위만 보고, 문서 머리에 범위를 적는다.

## 절차 (단계가 끝날 때마다 파일에 저장한 뒤 다음 단계로 간다)

1. **계획 제시** — 읽을 파일 목록, 단계별 산출물, 범위 제한을 먼저 보여 준다. 아직 파일을 쓰지 않는다.
2. **진입점** — 사용자가 호출하는 URL · 화면 · 프로시저 · main 을 찾아 `파일:줄번호` 와 함께 표로 정리한다.
   → `ARCHITECTURE.md` 의 "진입점" 절에 저장.
3. **의존 관계** — 진입점에서 실제로 호출 · include 하는 파일 · 클래스 · DB 객체를 따라간다. 호출 방향(누가 누구를 부르는지)을 화살표로 적는다.
   → `ARCHITECTURE.md` 의 "의존 관계" 절에 추가 저장.
4. **데이터 흐름** — 테이블 · 뷰 · 프로시저와 컬럼, 키, 관계를 스키마(`db/**/init/`)와 코드 SQL 에서 뽑는다. 어느 진입점이 어느 테이블을 읽고 쓰는지(R/W) 표로 만든다.
   → `ERD.md` 에 저장(mermaid `erDiagram` + R/W 표). `ARCHITECTURE.md` 에 흐름 요약을 덧붙인다.
5. **비즈니스 규칙 후보** — 조건 분기 · 검증 · 기본값 · 정렬 · 상태 전이 · 매직 넘버를 규칙으로 뽑는다.
   → `BUSINESS-RULES.md` 에 아래 형식으로 저장. 매직 넘버 표, "주석만 있거나 코드와 다른 것", "찾지 못한 것" 절을 둔다.
6. **교차 검증** — 같은 범위의 규칙을 코드에서 한 번 더, 독립적으로 뽑아 5단계 결과와 대조한다.
   - 새 서브에이전트(Agent, `general-purpose`)에 범위와 읽을 코드 파일 목록만 넘긴다. 이 에이전트는 `docs/` 를 읽지 않는다(5단계 결과를 보지 않는다).
   - 서브에이전트는 `CX-01` 부터 연번으로 규칙 · `파일:줄번호` · 근거 코드 원문을 적는다. 머리에 읽은 파일 · 읽지 않은 폴더 · 원칙을 적는다.
   - 받은 결과로 대조 표(`BR ↔ CX` · 일치 | BR 에만 | CX 에만 | 내용 다름)를 만든다. 일치가 아닌 행은 코드를 다시 읽어 판정한다. BR 이 틀렸으면 `BUSINESS-RULES.md` 를 고치고, 대조 표의 판정 열에 고친 내용을 적는다.
   → `CROSS-CHECK.md` 에 저장(CX 규칙 + 끝에 "대조 결과" 표).
7. **표본 점검 추천** — 사람이 코드와 직접 대조할 규칙 3개를 추천한다.
   - 반드시 **가장 그럴듯해서 검토 없이 넘어가기 쉬운 규칙** 1개를 포함한다.
   - 나머지는 6단계 대조에서 일치하지 않은 규칙, 주석 ↔ 코드 불일치 규칙, 추정이 섞인 규칙에서 고른다.
   - 규칙 ID · 고른 이유 · 확인할 `파일:줄번호` 를 답변에 적는다(파일에 쓰지 않는다).

## 규칙 형식 (BUSINESS-RULES.md)

```markdown
### BR-01 <한 줄 규칙 제목>
- 규칙: <조건이면 결과다 — 한두 문장>
- 근거: `파일:줄번호`[, `파일:줄번호`]
- 근거 코드:
  ```<언어>
  <근거 줄을 그대로 인용, 1~3줄>
  ```
- 확신도: 확실 | 추정
- 비고: <주석과 불일치 · 중복 구현 · 실행 확인 안 함 등>
```

- ID 는 `BR-01` 부터 연번. 근거 코드는 요약하지 않고 원문 그대로 인용한다.
- 코드를 실행 · 조회하지 않고 읽어서만 판단한 동작은 비고에 "추정, 실행 확인 안 함"을 적는다.

## 하지 말 것

- 존재하지 않는 함수 · 파일 · 테이블 · 컬럼을 적지 않는다. 문서에 이름을 쓰기 전에 Grep 으로 정의 위치를 찾고, 못 찾으면 쓰지 않는다.
- 호출 방향을 뒤집거나 추측으로 잇지 않는다. 실제 호출 · include · SQL 문이 있는 줄만 화살표로 연결한다.
- 코드에 없는 규칙을 만들지 않는다. "보통 이렇다", "이름으로 보아 이럴 것이다"는 규칙이 아니다. 근거 줄이 없으면 "찾지 못한 것"에 적는다.
- 주석 · 화면 문구 · 스키마 주석을 규칙의 근거로 삼지 않는다. 코드와 다르면 코드를 따르고 불일치를 비고에 적는다.
- 줄번호를 기억으로 적지 않는다. 인용하기 직전에 해당 줄을 다시 읽어 확인한다.
- 이관 대상(`modern/`)을 기준으로 레거시 동작을 "고쳐서" 적지 않는다. 버그처럼 보여도 코드 동작 그대로 적는다.
- 한 단계를 파일에 저장하지 않고 다음 단계로 넘어가지 않는다.
- 교차 검증(6단계)을 5단계 결과를 본 채로 직접 하지 않는다. 대조 결과가 모두 일치여도 대조 표를 생략하지 않는다.
